WEB ARXITEKTURA va HTTP asoslari 

Dasturiy mahsulot 0 holatdan ishchi holatiga kelguncha quyidagi bosqichlardan otadi:
1. Mijoz ehtiyoji: Muammo va talablarni organish.
2. Texnik topshiriq(TT): Bajarilishi kerak bolgan vazifalarni rsmiylashtirish.
3. Arxitektura: Sistema tuzilishi, malumotlar bazasi va texnologiyalarni tanlash.
4. Frontend/Backend/DB: Kod yozish va bazani shakllantirish bosqichi.
5. Testing: Xatoliklarni qidirish va bartaraf etish.
6. Deploy: Loyihani serverga joylashtirish va foydalanuvchilarga taqdim qilish.



Client-Server Modeli
Client-Server - Tarmoq arxitekturasi, unda vazifalar asosiy 2 turga bolinadi: 
1. Client(Mijoz): Foydalanuvchi interfeysi(Brauzer, mobile app). U foydalanuvchilarni malumotlarni qabul qilib oladi va serverga sorov yuboradi
2. Server (hizmat korsatuvchi): U uzoqdagi kompyuter (Backend-PHP/Python). U sorovlarni qabul qiladi, biznes mantiqni bajaradi, baza bilan muloqot qiladi va javob qaytaradi.

Http sorov va javob (Request/Response) tuzilishi: 
1. Request(sorov): 
    1.1 URL: Sorov yuborilayotgan manzil.
    1.2 Method: Bajariladigan amallar(Get, Post, Put, Delete).
    1.3 Headers: Qoshimcha malumotlar (Content-Type, Authorization Tokens).
    1.4 Body yuborilayotgan malumot (asosan Post/Put sorovlarda)

2. Response(Javob):
    2.1 Status code: Sorov natijasi kodi.
    2.2 Headers: Server va Javob haqida malumotlar.
    2.3 Body: Qaytgan malumot(HTML/JSON va h.k).

3. Http status kodlar:
Status kodlar serverning mijoz sorovigaa bergan javobning holatini bildiradi.
    3.1 200 OK: Sorov muvaffaqiyatli bajarildi.
    3.2 204 NO CONTENT: Sorov muvaffaqiyatli bajarildi lekin qaytariladigan malumot yoq.
    3.3 301 Moved Permanently: Manzil boshqa joyga mutlaq kochirilgan (redirect).
    3.4 400 Bad Request: Mijoz tomonidan notogri sorov yuborildi.
    3.5 401 Unauthorized: Avtorizatsiyadan otilmagan (login qilinmagan)
    3.6 403 Forbidden: Kirish ruxsat yoq(Huquq yetarli emas)
    3.7 404 Not found: Soralgan resurs yoki sahifa topilmadi.
    3.8 422 Unprocessable Entity: Validatsiya xatoligi (masalan: forma notogri toldirilgan).
    3.9 500 Internal Server Error: Serverning ichki koddagi xatoligi.

4. REST API va JSON Format.
    4.1 REST API(Represantational State Transfer): Client va server ortasida malumotlar almashish uchun standart qoidalar toplami. U resurslarga (masalan: /products) asoslanadi va standart Http methodlaridan foydalanadi.
        * GET /products - barcha tovarlarni korish
        * GET /products/1 - idsi 1 bolgan tovarni korish
        * POST /products - Yangi tovar qoshish
        * PUT /products/1 - idsi 1 bolgan tovarni ozgartirish
        * DELETE /products/1 - idsi 1 bolgan tovarni ochirish
    
    4.2 JSON(JavaScript Object Notation): Tizimlar orasida malumot almashish uchun eng ommabop va yengil matnli format. U Kalit-Qiymat(key-value) korinishda boladi:
        {
            "id": 1,
            "title": "Fjallraven - Foldsack No. 1 Backpack",
            "price": 109.95, 
            "men's clothing"
        }
